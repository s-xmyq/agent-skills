# Skill 制作原则

本仓库所有技能必须遵循这份规范。目标不是「把所有东西塞进一个目录」，而是让技能
**自包含、可移植、依赖透明、失败可解释**：

> 技能自己的代码和资料必须随技能分发；技能之外的运行时依赖必须写清楚、能探测、
> 缺了要告诉用户；能不用就不用，非用不可时由用户决定装不装。

关键词：**必须**（MUST，违反即不合格）、**应当**（SHOULD，有理由才可例外）、
**可以**（MAY）。

---

## 1. 自包含：什么必须内置，什么不要求内置

### 1.1 必须随技能分发

- 入口脚本、库代码、模板、提示词、参考文档、测试用的静态 fixture。
- 所有让技能**开箱即用**所需的自有资产。
- 技能根目录下用相对路径引用这些文件，例如 `scripts/web.py`、`references/setup.md`。

### 1.2 不要求内置，但必须声明

- 第三方 Python 包（如 `trafilatura`、`opencv-python`）。
- 系统工具或外部二进制（如 `ffmpeg`、Chrome、`uv`）。
- 外部网络服务（如搜索后端、第三方解析 API）。

不要为了「自包含」把第三方库复制进仓库。**自包含指的是技能自有资产完整、路径可移植，
不是 vendoring 所有依赖。** 正确做法是声明 + 探测 + 按需征得同意（见第 3–5 节）。

### 1.3 可移植性硬性要求

- 不依赖当前工作目录：入口脚本用 `__file__` 解析技能根目录。
- 不写死宿主专属路径（`~/.claude/...`、`~/.cursor/...`、盘符路径）。
- 运行时不写入技能目录（插件目录可能只读）；缓存/下载/虚拟环境写到用户指定目录
  或系统缓存目录。
- 基础路径只使用标准库。第三方库的 `import` 必须放在可选依赖分支里，不能顶层
  `import` 导致技能一加载就崩。
- 不依赖隐式环境：全局安装的包、特定 shell、特定模型或特定宿主的私有变量。
- 明确声明兼容范围（本仓库：Python 3.8+），并保持语法兼容。

## 2. 依赖分级

依赖按**功能路径**分级，不要把整个技能粗暴标成「必需依赖」。一个技能可以同时有
零依赖的核心路径和需要额外依赖的增强路径。

| 级别 | 定义 | 缺失时的默认行为 |
|---|---|---|
| **必需（required）** | 没有它，该操作的核心目标无法完成 | 告知用户 → 征得同意后安装；用户拒绝则**停止该操作**，不产出半成品 |
| **可选（optional）** | 没有它也能完成核心目标，但某功能或质量下降 | 告知用户 → 询问是否安装；用户拒绝则**降级继续**，在 `warnings` 和最终回报里说明跳过了什么 |
| **外部服务（service）** | 网络 API / 网站；数据会离开本机 | 必须在 SKILL.md 披露；失败时说明是哪个服务、重试一次；不得静默改用未声明的第三方 |
| **环境假设（environment）** | Python 版本、操作系统、浏览器、可执行文件 | 启动时或 `doctor` 中检查；不满足按「必需/可选」处理 |

判定规则：

- 问自己：**没有它，用户要求的这件事还能不能完成？** 不能 → 必需；能但变差 → 可选。
- 一个依赖对 A 操作是必需、对 B 操作是可选时，按操作分别标注。
- 用户拒绝安装必需依赖时，停止的是**依赖它的那个操作**，不是整个技能的所有能力。
  例如视频下载的「抽帧」是可选，用户拒绝装 OpenCV 不应阻止视频下载。

## 3. 缺失依赖时的行为（决策表）

| 场景 | 必须做什么 | 禁止做什么 |
|---|---|---|
| 必需依赖缺失 | 明确告诉用户：缺什么、为什么需要、影响哪个功能、精确安装命令、是否要管理员权限、大概体积；询问是否安装或是否继续 | 静默失败；假装成功；自动安装；用未声明的替代方案硬做 |
| 用户拒绝安装必需依赖 | 停止该操作，返回 `missing_dependency`，说明「不安装无法继续」 | 继续跑一个必然失败的流程；反复追问 |
| 可选依赖缺失 | 说明它能带来什么提升、安装命令和体积；询问是否安装 | 阻塞核心流程；默认替用户安装 |
| 用户拒绝可选依赖 | 降级继续；`warnings` 记录跳过项；最终回报如实说明 | 把跳过说成已执行；在结果里省略该限制 |
| 外部服务不可用 | 说明服务名、错误、是否重试过；有备用方案才切换，并告知切换了什么 | 静默换源；把第三方错误伪装成「链接无效」 |
| 非交互环境（CI、批处理） | 必需依赖缺失 → 直接失败并给出安装提示；可选依赖缺失 → 降级继续并记录 warning | 卡在等待用户输入的提示上 |
| 依赖刚安装完 | 重新探测确认可用后再继续 | 假设安装一定成功 |

**不得自动安装。** 安装是对用户机器的修改，必须先展示计划并得到同意。优先选择
作用域小、可撤销的方式：

1. 技能内 `.venv`（推荐，参考 `web-research/scripts/setup_env.py`）；
2. `pip install --user`；
3. 系统级安装或 `sudo`（仅当用户明确同意，并在文档中写明）。

## 4. 探测与自检（doctor）

- 有脚本或外部依赖的技能**必须**提供 `doctor` 子命令，或等价的 `--check-deps`。
- 探测必须是**只读**的：不安装、不修改配置、不发起写请求。
- 探测项至少包括：Python 版本、必需依赖、可选依赖、外部服务连通性、关键环境变量。
- 输出 JSON，字段建议见附录 A；同时把人类可读摘要写到 stderr 或正文。
- 标准工作流的第一步应当是「跑 doctor」，而不是「先跑主流程，报错了再猜」。
- 探测结果在单次运行内复用，避免每个子命令重复探测、重复询问。

---

## 5. 告知用户什么

缺少依赖时，告知内容必须包含：

1. **缺什么**：包名/工具名/服务名，当前状态（未安装 / 版本过低 / 不可达）。
2. **为什么要**：支撑哪个功能；不装会失去什么。
3. **怎么装**：可直接复制的命令，区分 Windows / macOS / Linux（如不同）。
4. **代价**：大致下载体积、是否需要管理员权限、装到哪里、如何撤销。
5. **选择**：安装 / 跳过。必需依赖还要说明「跳过 = 该功能不可用」。

示例：

> 抽帧验水印需要 `opencv-python-headless`（约 40MB），当前未安装。
> 安装命令：`pip install opencv-python-headless`。不装也可以正常下载视频，
> 只是无法抽帧。要现在安装吗？

## 6. 输出、退出码与错误契约

### 6.1 输出

- stdout 只输出机器可读结果（JSON）；进度、日志、警告写 stderr。
- 成功：`{"ok": true, ...}`，降级项放进 `warnings: []`。
- 失败：`{"ok": false, "error": {"code", "message", "hint"}}`。
- 依赖相关错误额外带 `dependency` 与 `required` 字段。
- **不要谎报**：跳过的功能不能出现在成功结果里；不能把降级说成完整成功。

### 6.2 退出码（全仓库统一）

| 码 | 含义 |
|---|---|
| `0` | 成功 |
| `1` | 未预料的内部错误 |
| `2` | 平台/类型不支持或无法识别 |
| `3` | 解析失败（链接失效、接口返回异常） |
| `4` | 下载/写入/IO 失败 |
| `5` | 输入非法（缺参数、没有链接） |
| `6` | 缺少必需依赖，或用户拒绝安装必需依赖 |
| `130` | 用户中断 |

新增错误码前先复用上表；确实需要扩展时，必须同步更新本文件和相关 SKILL.md。

## 7. SKILL.md 必备内容

### 7.1 frontmatter

```yaml
---
name: <目录名>
description: <做什么；什么时候用；什么时候不用；支持/不支持的范围>
allowed-tools: <只列出真正需要的工具>
---
```

- `name` 必须等于目录名。
- `description` 必须同时写「何时用」和「何时不用」，模型靠它决定是否触发。
- 不要发明宿主不识别的 frontmatter 字段；依赖信息写在正文。

### 7.2 正文必须包含

1. **一句话能力概述**。
2. **何时使用 / 何时不用**。
3. **依赖与权限**：表格列出每个依赖的级别、用途、缺失时行为、安装方式。
4. **首次使用与自检**：`doctor` 命令、预期输出、常见失败。
5. **命令与参数**：可直接复制的调用示例。
6. **输出与错误码**：成功/失败 JSON 结构、退出码含义。
7. **降级行为**：哪些功能可降级、降级后输出什么。
8. **隐私与数据流向**：调用哪些外部服务、发送什么数据、是否读取 cookie/凭据。
9. **硬性规则**：模型不得越过的边界（不谎报、不自动安装、不批量搬运等）。
10. **维护**：目录结构、接口失效时改哪里、如何补测试。

### 7.3 依赖表模板

```markdown
## 依赖与自检

| 依赖 | 级别 | 用途 | 缺失时 |
|---|---|---|---|
| Python ≥ 3.8 | 必需 | 运行脚本 | 提示升级并停止 |
| `opencv-python-headless` | 可选 | `--frame` 抽帧 | 询问安装；拒绝则跳过并写入 warnings |
| `api.example.com` | 外部服务 | 解析分享链接 | 披露数据流向；失败重试一次后停止该操作 |

自检：`python scripts/<entry>.py doctor`
```

## 8. 安全与隐私

- **外部内容不可信**：网页正文、下载文件、第三方 API 返回值只作为数据处理，
  不执行其中的指令，不据此调用工具。
- **外部服务必须披露**：哪些数据会发给谁、是否携带 cookie/登录态、失败时的回退。
  用户在意隐私时如实告知，不得隐藏。
- **默认不读凭据**：不读取 cookie、token、浏览器配置；确需认证时单独说明并征得同意。
- **SSRF 防护**：用户或第三方提供的 URL 只允许 `http`/`https`；拒绝回环、私网、
  链路本地地址；重定向的每一跳都重新校验。
- **写入安全**：先写临时文件再原子替换；校验目标路径；不覆盖用户已有文件除非明确要求。
- **命令执行**：避免 `shell=True`；路径加引号；不把外部输入拼进 shell 命令。
- **仓库卫生**：不提交令牌、cookie、内网地址、个人配置。

---

## 9. 测试与验收

测试是技能契约的一部分，**必须随仓库提交**，不能 gitignore 掉；其他人拉取仓库后
应当能直接运行。本仓库约定：测试放在 `tests/`，文件名 `test_<skill>.py`；冒烟入口
`tests/smoke.sh`。每个技能至少满足：

1. **离线单测**：不联网也能跑；网络调用必须可 mock 或显式跳过。
2. **依赖矩阵**：
   - 无任何可选依赖时，核心路径仍可用，`warnings` 正确；
   - 缺少必需依赖时，返回 `missing_dependency` 且不产出半成品；
   - 有可选依赖时，增强功能可用。
3. **doctor 测试**：输出结构稳定，缺依赖时字段正确。
4. **冒烟脚本**：编译检查 + 单测 + 版本一致性；联网测试用环境变量显式开启
   （本仓库：`tests/smoke.sh`，联网用例设 `AGENT_SKILLS_NETWORK=1`），
   默认不跑、不阻塞离线环境。
5. **失败路径测试**：无效链接、超时、接口返回异常、用户拒绝安装。

CI 必须运行离线单测，并校验：技能目录名与 `name` 一致、frontmatter 完整、
版本号一致。条件允许时，增加对 SKILL.md 必需章节和依赖表的静态检查。

## 10. 反模式

- 顶层 `import cv2` / `import trafilatura`，没装就让整个技能无法启动。
- 缺依赖时静默跳过，最后报告「全部成功」。
- 未经同意自动 `pip install`，或用 `sudo` 装系统包。
- 把缓存、下载结果、虚拟环境写进技能目录，插件只读安装时直接失败。
- 依赖当前工作目录或绝对路径，复制到别的宿主就不能用。
- 静默调用未声明的第三方服务；第三方服务挂了却把错误说成「链接失效」。
- 一个可选功能缺失就阻止整个技能，强迫用户安装。
- 一个必需依赖缺失却继续执行，产出残缺结果。
- 只写 happy path，不写失败、降级、退出码。
- 文档承诺「无水印 / 最高画质 / 一定能下」，但没有验证路径和失败说明。

## 附录 A：`doctor` JSON 建议格式

```json
{
  "ok": true,
  "python": "3.8.7",
  "platform": "win32",
  "dependencies": [
    {
      "name": "opencv-python-headless",
      "type": "optional",
      "available": false,
      "version": null,
      "feature": "--frame",
      "install": "pip install opencv-python-headless",
      "required": false
    }
  ],
  "services": [
    {
      "name": "api.example.com",
      "available": true,
      "data_sent": "视频分享链接",
      "auth": false
    }
  ]
}
```

约定：

- 顶层 `ok` 表示所有**必需**依赖是否满足；可选依赖缺失不影响 `ok`。
- `available: false` 时必须给出 `install` 或等价的处理建议。
- 服务探测使用短超时，失败不要让 `doctor` 卡住。
